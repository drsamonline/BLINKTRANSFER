Capabilities

Built to move data with nothing in between

Everything BlinkTransfer does happens between two screens and a camera lens — no router, no pairing handshake, no cloud round-trip.

01

Completely offline

No internet, Bluetooth, or cables needed. The only channel is light from one screen into the other's camera — ideal for air-gapped or untrusted environments.

02

Animated QR at 20 FPS

A stream of QR frames — 1600 bytes each — is rendered at 20 FPS, carrying 1573 bytes of data per frame plus a 27-byte header.

03

Smart compression

Images are re-encoded as JPEG with adjustable quality (10–90%), while other files use Gzip via the CompressionStream API — so fewer frames are needed.

04

Multi-file sessions

Send several files in a single session. Metadata travels in a header QR before the animated data stream begins.

05

CRC-16 checksums

CRC-16 error detection runs on every QR frame, so a misread symbol is caught instead of corrupting the received file.

06

Installable PWA

Installable and works offline after the first load, thanks to a service worker. The UI is mobile-optimised and responsive.

Protocol

How a transfer works

One device transmits, the other receives. Both run the same app — pick a role and point the camera.

Sender

  1. Select files (multiple supported).
  2. Adjust image quality if needed (10–90%).
  3. A focus-assist pattern displays for 2 seconds.
  4. A header QR shows the file metadata.
  5. The animated data stream begins at 20 FPS.
  6. Keep the screen visible until the transfer completes.

Receiver

  1. Tap Receive and grant camera permission.
  2. Point the camera at the sender's QR code.
  3. A progress bar shows the symbols collected.
  4. When complete, tap Save Files to download.
Demo

Two screens, one optical link

The interface is deliberately minimal: a sender screen that animates QR frames, and a receiver screen that scans them and tracks progress.

  • No setup, no pairing. Open the page on both devices and choose a role.
  • Live in the browser. A Web Worker-friendly QR generator and the camera API do the work.
  • Runs offline. Once loaded, the service worker serves the app without a network.

FAQ

Questions, answered

Does BlinkTransfer need an internet connection?
No. It is completely offline — no internet, Bluetooth, or cables needed. The transfer channel is the sender's screen and the receiver's camera.
What are the file-size limits?
Up to 5 MB per file and 20 MB for a whole batch. Multiple files can be sent in one session.
How fast is a transfer?
Practical speed is roughly 30 KB/s — the animated QR stream runs at 20 FPS and each frame carries about 1573 bytes of data.
How does compression work?
Images are compressed as JPEG with adjustable quality (10–90%). Other files use Gzip through the CompressionStream API. Fewer bytes means fewer frames and a faster transfer.
Which browsers are supported?
Chrome 80+ (recommended), Firefox 114+, and Safari 16+. The app relies on the CompressionStream, getUserMedia, and wakeLock APIs.
Is it installable, and does it work offline?
Yes. It is a PWA: installable and works offline after the first load, thanks to a service worker that caches the app.
Is it free and open source?
Yes — BlinkTransfer is released under the MIT license, and the full source is on GitHub.
